# Redstyle ppt skill（党政主题）

当用户需求为生成党政主题类的PPT或希望生成党政主题风格的PPT时，支持可直接执行的PPT“策划 → 大纲 → 生成/编辑 → 质检 → 迭代”规范：

- 工作流与工具调用：以 ppt_agent 为唯一的PPT生成/编辑执行器；用结构化 prompt（user_prompt/materials/outline）驱动产出满足要求与**党政主题风格（庄重规范 + 论点式标题 + 政策/数据依据 + 信息密度高但不拥挤 + 可追溯来源）**的PPT。

---

## 1. 任务类型判定

先判定用户诉求属于哪类，再选择对应流程：
 
1) PPT生成：检索与整理素材 → 写大纲 → 调用 ppt_agent 生成  
2) PPT编辑：对已有PPT按页面或全局修改 → 调用 ppt_agent 执行  

---

## 2. 工具与约束

### 2.1 工具使用原则

- 信息检索：general_search + web.fetch
- 用户本地文件上传：FileBatchUpload / FileUpload（先上传拿远程URL，再交给ppt_agent）
- PPT生成/编辑：必须通过 ppt_agent

### 2.2 严格限制（重要）

- 背景图仅允许使用本规范指定的 references 素材；调用 ppt_agent 时禁止自行搜索/替换背景图
- 禁止在外部预生成图表图片：不要用 matplotlib/plotly 等先画图再给 ppt_agent；在大纲中提供原始数据 + 图表类型建议，由 ppt_agent 原生渲染
- 禁止在 prompt 中使用本地文件路径；ppt_agent 只能使用远程URL
- 任何需要生成或编辑PPT的动作，都必须通过 ppt_agent 工具调用执行

---

## 3. ppt_agent 调用规范（结构化prompt）
### 3.1 ppt_agent 工具定义与调用方式

ppt_agent 是一个**工具（function tool）**，必须以标准的**工具调用（tool call / function call）**方式来调用。其 schema 定义如下：

```json
{
    "type": "function",
    "function": {
        "name": "ppt_agent",
        "description": "专业PPT策划与设计助手。用于识别PPT需求并完成PPT大纲撰写、PPT生成、PPT编辑/改写/删除等任务；支持基于检索与素材收集生成PPT，支持用户提供信息生成PPT，支持参考PPT模板生成PPT；支持对已有PPT按页面或全局进行修改",
        "parameters": {
            "type": "object",
            "properties": {
                "canvas_ids": {
                    "description": "需要ppt_agent关注的PPTID",
                    "type": "array",
                    "items": {
                        "type": "string"
                    }
                },
                "prompt": {
                    "description": "创建或编辑的Prompt",
                    "type": "string"
                }
            },
            "required": []
        }
    }
}
```
### 3.2 参数说明

- canvas_ids（可选）：编辑已有PPT时传入PPT ID列表
- prompt（核心）：必须采用三段式结构组织

### 3.3 prompt 三段式模板

```yaml
user_prompt: |
  [用户原始需求，原样保留完整诉求：主题、受众、页数、风格、限制条件等]
  [如用户提供了图片/文件/数据，必须逐项列出，并要求优先使用]
  [如用户提供的prompt是英文的，则要求需要生成一个纯英文的PPT]
  [强调：背景图必须使用本规范指定的素材链接（见 outline 的“背景图规则”），禁止自行搜索或替换背景图]
  [强调：不要使用任何蒙层]

materials: |
  [整理后的完整素材内容：背景、论点、数据、案例、逻辑链条]
  [关键数据与引用来源需写清楚]

outline: |
  [页级结构化大纲 page-by-page]
  [每页：论点式标题、核心要点、图表/表格建议、数据与来源、必要的页面规范]

  约束：必须按“背景图规则”使用指定背景图；标题用低饱和度金黄色，正文用正黑色；不额外添加配图（除非用户附件提供），仅用图表与表格承载证据。
```

### 3.4 用户素材优先原则

- 用户提供的图片/文件/数据表/参考PPT优先级最高：必须在 user_prompt 中完整列出，并在 outline 中优先映射到对应页面
- 不额外提供用户附件以外的配图与背景图

### 3.5 用户文件/图片上传流程（必须）

**关键规则**：ppt_agent 只能使用远程 URL 链接，**绝对不能使用本地文件路径**。用户提供的所有图片/文件必须先上传获取远程链接后再传给 ppt_agent。

处理步骤：

2. **文件上传**：使用 `FileBatchUpload`（批量）或 `FileUpload`（单个）将所有图片/文件上传，获取远程 URI（包括本规范指定的背景图素材）
2. **文件上传**：使用 `FileBatchUpload`（批量）或 `FileUpload`（单个）将所有图片/文件上传，获取远程 URI
3. **记录映射关系**：将每个文件的本地路径、远程 URI、文件内容描述记录下来，形成映射表

示例流程：

```
# 步骤1：解压用户上传的压缩包
shell: unzip /path/to/用户素材.zip -d /path/to/workspace/素材目录/
shell: ls -la /path/to/workspace/素材目录/

# 步骤2：批量上传所有图片文件
FileBatchUpload(path_list=[
  "/path/to/workspace/素材目录/图片1.png",
  "/path/to/workspace/素材目录/图片2.png",
  "/path/to/workspace/素材目录/图片3.png"
])

# 步骤3：上传后会返回每个文件的远程 URI，例如：
# 图片1.png → https://lf-mcphubtraining.100xfl.com/obj/.../图片1.png
# 图片2.png → https://lf-mcphubtraining.100xfl.com/obj/.../图片2.png

# 步骤4：在 ppt_agent 的 prompt 的 outline 中使用远程链接
outline: |
  第2页：XXXX
  - 配图:
    - 图片链接: https://lf-mcphubtraining.100xfl.com/obj/.../图片1.png
      图片描述: 用户提供的XXX图片
```

## 4. 生成/编辑的推荐执行流程

### 4.1 PPT大纲撰写流程（先内容，后图片）

1) 需求拆解：提取 3–5 个核心维度（优先级：核心论点数据 > 关键案例 > 背景知识 > 补充观点）  
2) 聚焦式搜索：每轮不超过 3 个关键词，并行搜索；总轮次控制在 3 轮左右  
3) 精读：对高价值链接使用 web.fetch 获取更完整内容  
4) 信息充分性判断：核心要点数据与案例齐备即可停止搜索  
5) 输出页级结构化大纲（详见第7节模板）  

### 4.2 PPT生成流程（必须走完整三段式prompt）

1) 先整理 materials（完整报告式内容）  
2) 再写 outline（页级结构化大纲）  
3) 调用 ppt_agent 生成PPT  
4) 只需确认返回结果中包含有效的飞书slides链接即可视为成功  

### 4.3 PPT编辑流程

- 页面级编辑：指定 canvas_ids + page_id（或页序号），在 outline 写清改动动作与目标效果  
- 全局编辑：在 outline 给出所有页面顺序，并逐条说明全局改动规则（配色、字体、布局、信息密度、图表样式等）

## 5. 党政主题“完成标准”（Definition of Done）

- 每页标题是“论点式标题”（一句话结论），不是话题词
- 每页至少一个证据载体：图表/表格/矩阵/时间轴/量表/案例框
- 关键数字与政策表述可追溯到来源（URL/报告/财报/政策文件）或明确标注为估算并给出方法
- 版式满足强制规则：对比度、直角矩形、默认无边框、无遮挡、不溢出
- 信息密度高但不过载：超过阈值要拆页或重构

---

## 6. 党政主题样式规范（Style Specs）

### 6.1 配色

- TITLE：#B08A2E（低饱和度金黄色，用于标题与少量关键强调）
- TEXT：#000000（正文与大多数文本，正黑色）
- SUBTEXT：#666666（注释、来源、次要信息）
- GRIDLINE：#E6E6E6（分隔线、表格细线、辅助网格）

### 6.2 背景图规则（必须）

- 特殊页（封面页/目录页/总结页）：使用同一张背景图（封面图），从 [references/特殊页背景图]路径下取用
- 内容页（除特殊页外所有页面）：统一使用 [references/普通内容页背景图/]路径下取用
- ppt_agent 调用时：必须将上述背景图上传为远程 URL，并在 outline 中显式写出对应页面使用的背景图 URL；禁止 ppt_agent 自行搜索/替换背景图
- ppt_agent 调用时：不允许使用任何蒙层


### 6.3 字体体系

- 正文衬线字体（推荐）：思源宋体 / Noto Serif CJK SC；备选：宋体（SimSun）、Songti SC
- 标题：18pt
- 正文：11pt
- 注释/来源：9pt
- 最小字号：7pt

## 7. 强制规则（Must Rules）

### 规则1：强调色背景必须白色文字

只要背景为深色/高饱和度色块（如标题条、表头、洞察框标题条、序号标签、强调区等），文字必须为白色以保证对比度。

### 规则2：论点式标题

每页标题必须是一句话结论，包含方向/强弱/比较/原因/影响等信息，不允许仅写“市场分析/竞争格局/用户数据”等话题词。

### 规则3：高信息密度但不拥挤

以“字符数/面积”作为约束：

- safe：<50 字符/平方英寸
- warning：50–70 字符/平方英寸
- critical：>70 字符/平方英寸（优先拆页或重构信息组织）

处理手段（用于让内容更详细）：

- 增加数据标注与图例信息，让图表“自解释”
- 添加洞察框填补空白区域：1句结论 + 1个数字支撑 + 1句含义
- 缩小字号（优先 9→8→7），或扩容容器
- 放大图表占比（目标 60–70% 页面空间）
- 拆分为2–3页，保持逻辑连续

### 规则4:如果页面上有数据，则左下角要有脚注（数据来源方说明）

当PPT对应那一页有数据表达或论据时，必须在左下角放置脚注，包含数据来源方信息，建议结构：

- 来源：机构/报告/财报/网站（可含URL或报告名）

脚注样式必须遵从同一个格式：SUBTEXT 颜色，9pt，左下角对齐，尽量单行或两行以内。

## 8. “内容要更详细”的执行清单（来自两份文档的合并）

### 8.1 大纲写法（必须具体化）

- 每页 3–5 条“具体要点”，每条要点都写“观点 + 证据（数据/案例/引用）”
- 对比类：列出对比维度与具体内容点（不要写“对比A/B”这种空话）
- 时间线/流程：按阶段列清楚每步关键信息
- 关键数据写出具体数值（增长率、占比、差值、规模、CAGR），并标注来源口径

### 8.2 图表页写法（让证据更密）

- 必须提供原始数据（结构化列出），并指定图表类型
- 增加关键点标注（同比、CAGR、拐点、Top项差距）
- 图例扩展为“类别 + 数值 + 占比/趋势”

### 8.3 案例页写法（让故事更完整）

- 案例至少包含：背景、动作/过程、结果（量化）、启示/可复制点
