# ADR-0013: 交互菜单（G-6）——一条命令之后只有选择题

- **状态**: Accepted
- **日期**: 2026-09-06
- **关联**: ADR-0011（bootstrap `up`）、ADR-0012（易用引导 UX）、用户约束（2026-09-06：**"我觉得应该让用户做选择题，一个命令之后，最好就别出现命令了吧？！"**）
- **仓库**: Anaphase（src/bin/up.rs）

## 1. 背景

G-5 的 `up` 输出引导四段式（欢迎/前置检查/启动/下一步），但"[下一步]"
仍在**打印命令**（打开驾驶舱要复制一条长命令）。用户明确：一个命令之后
**不要再出现命令**——应该让用户做选择题。这是"易用性不是装饰"的收口：
命令记忆成本降到零，交互面收敛为 4 个数字。

## 2. 决策

### D1: `up` 启动后端后进入交互菜单（tty 时）

菜单四选项（数字选择，Enter = 默认）：
1. **打开驾驶舱**（默认）——前台运行 Cellrix cockpit，退出后回菜单
2. **查看状态**——物理探测两端口 + 实时 snapshot 摘要（认知状态/经历/ledger 条数）
3. **配置说明**——config.toml 关键项 + 当前值（reasoning/模式/端口）
4. **停止并退出**（q）——break 循环 → 子进程回收 → "stack down"

**决策形态：选择题，不是命令提示。** 驾驶舱从菜单直接拉起，不再复制
长命令；状态由程序自己探测（物理事实），用户不输入任何查询语句。

### D2: 非 tty 自动降级为挂起模式

stdin 非终端（管道/脚本/CI）→ 跳过菜单，保持 G-4 行为（挂起等 Ctrl+C）。
判断用 `std::io::stdin().is_terminal()`——物理事实，无参数开关
（按需驱动：交互用户要菜单，脚本用户要挂起，同一二进制两态）。

### D3: 状态 = 物理探测 + 真实 snapshot，无新依赖

- 端口探测：`TcpStream::connect`（物理事实）
- snapshot 摘要：手写 HTTP GET（`/v1/agent/snapshot`，ADR-0010 契约）+
  `serde_json`（主依赖已有）——不新增 crate，一条 HTTP 读全

### D4: 菜单循环保持确定性

`parse_choice` 纯函数（6 单测：默认/数字/q/未知输入）；未知输入 → 重提示
（不猜测、不静默执行）；每次循环后 `try_wait` 收割崩溃子进程（诚实反映
物理状态，不假装一切正常）。

## 3. 验证（已通过）

1. `cargo test` 135 passed（132 + 3 parse_choice，无回归）
2. **pty 交互实测**：起全栈 → 菜单 → 选 2（状态：Tentacle/Anaphase 运行中 +
   认知状态 Perception + ledger 0 条，真实 snapshot）→ 回菜单 → 选 4（退出）
   → stack down → 端口全清
3. 非 tty 模式（python Popen 无 tty）→ 挂起等待 SIGINT（G-4 行为保持）

## 4. 后果

**正面**：一条命令之后零命令——选择题闭环（开驾驶舱/看状态/配置/退出）；
菜单本身即"帮助"（不再需要 README 背命令）；状态一键真实。

**代价/缺口**：
- 菜单是行式数字选择（非全屏 TUI）——与驾驶舱 TUI 形态一致，保持
  确定性优先；全屏菜单/方向键属 G2（Web 面板）演进项。
- 配置说明只读（打印路径与当前值），不改写 config.toml——修改留给
  用户编辑器（自动改写配置是高风险动作，留待引导向导 G7 评估）。
- cockpit 仍需 Cellrix 已构建二进制（fail-open warn 提示）。
