# ADR-0041: 周期身份唯一化（Period Identity）—— 事件流的存储键不再与输入同构

- **状态**: Proposed（待人类批准）
- **日期**: 2026-09-17
- **决策范围**: anaphase-helix（`session_events.rs` 开流 / `contract::derive_job_id` 的调用点 / ledger 与 trace 的 join key）／ Cellrix（周期列表与链投影，消费侧）
- **关联**: ADR-0003（确定性 + 字节级 replay）、ADR-0006（会话即经历）、ADR-0026（会话事件流 `run-<12hex>` join key）、ADR-0035（判据拆分）、`Cellrix:ADR-0021`
- **引用约定**: 本文不带仓名的 `ADR-XXXX` 一律指 `anaphase:ADR-XXXX`。

---

## 一、背景：顺序错乱是可证的三层叠加

### 1.1 现象

人类报告：**点开一段经历，内容与自己的对话顺序混乱**（并提示"看时间戳"）。

### 1.2 三层因果（逐层实测）

**第一层——周期身份由输入派生。**
`job_id = derive_job_id(user_input)`（FNV-1a，ADR-0006 的确定性 replay）。
于是 **同一个问题问两次，必然得到同一个 job_id**。

**第二层——同 id 覆写同一文件。**
`SessionEventStream::open`（`src/session_events.rs:113-126`）用 `truncate(true)`：

```rust
// One period = one event file (truncate). job_id derives from the
// input (ADR-0006 deterministic replay), so a re-sent identical
// input lands in the same file — the period ledger holds the LATEST
// execution, and the full history lives in the Tuck audit chain.
let file = fs::OpenOptions::new()
    .create(true).write(true).truncate(true).open(&path)?;
```

注释已预见"最新一次胜出"，**但没预见第三层**。

**第三层——别的周期仍指向那个被覆写的 id。**
子周期的 `context/inject.resume_from` 存的是**父的 job_id 字符串**。父文件被覆写后，
这个引用仍然成立，只是它现在指向**另一次（更晚的）执行**。

### 1.3 铁证

`run-32c4be74a996a40d`（子）← `run-9e901b965a772d51`（父）：

| 时刻 | 事件 |
|---|---|
| 2026-09-15 06:1x | 问「你是谁?」→ 周期 A（job_id `run-9e901b...`） |
| 2026-09-15 06:19:10 | 问「今天北京天气?」→ 续接 A（`resume_from = run-9e901b...`） |
| 2026-09-15 17:01:07 | **又**问「你是谁?」→ 同一 job_id → **A 的文件被截断重写** |

结果：A 的 `first_ts = 17:01:07`，其子 `first_ts = 06:19:10`。
**父比子晚 11 小时** ⇒ 按 `resume_from` 顺序渲染即时间倒流。
实测全库 51 条血缘路径中 **5 条时间戳非单调**，全部源于此。

补充证据：**129 个事件文件中 8 个含多组 `turn/start`**（最多 7 组；
`run-c92cf339efa516de` 的两组相隔 **6 天**，`run-bce20dd603d5770e` 相隔 54 分钟）。
这 8 份全在 2026-09-07 ~ 09-13，**09-15 之后为 0** —— 说明 `truncate` 确实防住了"一个文件装多期"，
**但防不住"覆写被引用的父"**。

### 1.4 这不是 `Cellrix:ADR-0021` 引入的

该 ADR 把链窗口从"根的全部子树"收窄为"根→所点周期的血缘路径"，**缩小了错乱范围**
（旧 BFS 会把根的其他分支也并进来），但真因在存储键，与窗口语义无关。
`Cellrix:ADR-0021` 的代码注释早已标注此点：`L0 — TEMPORARY ... retire when anaphase provides session_id`。

## 二、决策

### D1：周期身份与输入解耦——存储键必须唯一

事件流文件是**周期的存储身份**。它必须满足：**一次执行 = 一个文件，且永不被另一次执行覆写。**

`derive_job_id(input)` 保留其原义（由输入确定的**派生基名**，可读、可复现），
但**不再是存储键的全部**。

### D2：分配策略——冲突时后缀，旧键不动

开流时若目标路径已被占用，依次尝试 `run-<hash>-2`、`-3`…，取第一个空闲名。

选择它的理由（对齐 DNA「物理事实优先 / 极致复用」）：

- **不引入时钟**：无需时间戳，无并发竞态，纯由文件系统状态决定
- **旧键永不改**：首个周期保持 `run-<hash>`，**现存链引用继续有效**（不迁移、不重写历史）
- **确定性**：同一目录状态下分配结果唯一，replay 可复现

### D3：一个身份，不是两个

**唯一键即 trace id**。它同时用于：

- 事件文件名
- ledger / evidence 的 `job_id`
- Tuck 审计链的 `x-tuck-trace` 与正文 trace
- `resume_from` 的取值
- 面板的周期键与链连接

**不允许**"派生基名做 trace、后缀做文件名"的两套身份——那正是"一个事实两处定义"。
（当前 `derive_job_id` 是**一处**推导，本决策保持这一点，只在其后追加唯一化步骤。）

### D4：`resume_from` 携带**确切的父键**

面板续接时把所选周期的**存储键**原样回传；服务端据此取其摘要。
不接受基名回退匹配（那会重新引入歧义）。

### D5：遗留多组文件不改写，读取侧单独处置

8 份历史多组文件（09-07~09-13）**原文保留**（历史永不删除）。
其投影修正属消费侧（Cellrix 面板按 `turn/start` 分组），**不在本 ADR 范围**，另行处置。

## 三、影响

### 正面
- 链不再指向被覆写的周期 ⇒ 顺序错乱的时间戳根因消失
- 一个周期一个文件，`count` / `first_ts` / `last_ts` / `parent` 恢复名实相符
- trace 唯一 ⇒ Tuck 审计链与正文 trace 的 join 不再混入两次执行
- 无迁移、无时钟、无并发风险

### 代价与风险
- **已丢失的历史不可恢复**：被覆写的那次执行内容已不存在（Tuck 审计链保留**元数据**，正文 trace 保留**正文**）——本 ADR 只能阻止新的丢失
- 同输入重复执行会产生多个文件 ⇒ `/v1/sessions` 列表更长（**如实**，不再靠覆写掩盖）
- 依赖"文件已存在即冲突"的判断：若某次执行中途崩溃留下空文件，会被当作已占用（可接受；空文件本身也是事实）
- **`ADR-0003` 的字节级 replay 契约需要一次核对**：两次同输入执行现在会产生两个文件，若某条 replay 测试比较的是"文件名/路径"而非"行内容"，需相应调整——**本 ADR 要求先实测确认，不得假定**

## 四、不解决什么（诚实边界）

| 不解决 | 原因 |
|---|---|
| 已被覆写的父节点内容 | 数据已丢失（Tuck 审计链只有元数据） |
| 8 份历史多组文件的投影歧义 | 消费侧问题，D5 另议 |
| `answer.delivered` 判据名不副实 | 它检查**工具返回值**（自注 "delivery confirmed at tool edge"），不检查"用户是否拿到答案"。独立问题，另议 |
| 面板侧"按时间戳排序"的诉求 | 本 ADR 修好根因后，`resume_from` 顺序与时间戳应自然一致；若仍不一致，说明还有第二个根因，**不得用排序掩盖** |

---

## 五、替代方案

| 方案 | 否决理由 |
|---|---|
| 继续覆写，只让面板按时间戳排序 | **用排序掩盖数据丢失**：被覆写的父内容仍是错的，只是排得好看 |
| `job_id` 直接改成含时间戳/随机 | 破坏 ADR-0003/0006 的确定性 replay 契约，且引入时钟依赖与并发竞态 |
| 每次执行都追加到同一文件（不平铺） | 已实测会产生多组 turn（8 份历史文件即此形态），消费侧无法分辨周期边界 |
| 把周期身份交给未来的 `session_id` 容器 | 方向正确但**没有时间表**；本 ADR 是它的最小前置（先让键唯一），不与之冲突 |
