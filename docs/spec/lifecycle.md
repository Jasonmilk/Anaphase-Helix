# Anaphase-Helix 生命周期协议（spec/lifecycle.md）

> **分卷 v1.0**（2026-08-28）｜ 继承 VISION 卷 E + 架构蓝图 v11.0 动态代谢 ｜ 方法论 DNA v2.0

## E.1 纪元代谢（Epoch Metabolism）

- **纪元（Epoch）**：Anaphase 的每次唤醒称为一个纪元
- **疲劳线**：Token 预算消耗达 **80%** 时，触发记忆结网，准备重生
- **凋亡线**：Token 预算消耗达 **95%** 时，强制结束当前纪元，输出阶段性结论
- **重生（Rebirth）**：清空短期工作记忆，携提炼后的意图进入下一个纪元

## E.2 强制苏醒（Awakening）

每个纪元开始，Anaphase 调用 `wake_up()`，读取上一纪元留下的认知脱水（`session_notes.json`），实现跨接力记忆传承。
**这不是 trace_id 审计链路，而是"认知重载"——让 Helix 醒来时知道前世走到了哪一步。**

## E.3 认知脱水（Dehydration）

每个纪元结束前，Anaphase 调用 `dehydrate()`，用轻量 LLM 将历史对话压缩为简报，供下一纪元加载。
本质是**跨纪元上下文压缩**，与 Mind 的 MSC 协议互补：
- **MSC**：处理"同工序内上下文"
- **脱水**：处理"跨工序/跨纪元上下文"

## E.4 工作记忆提纯（Working Memory Pruning）

- 突触返回的原始工具输出（网页源码、长日志）**绝不直接**进入上下文
- 必须经**预压缩**，仅保留与当前任务相关的核心段落或摘要
- 上下文按"绝对目标 / 静态指令区 / 短期上下文（已提纯）/ 长程记忆片段（独立）/ 代谢状态"分区，防止超载

## E.5 物理隔离沙盒

不同任务在物理目录隔离运行（`/workspaces/{task_id}/`），互不污染。任务结束后沙盒可保留或销毁。

## E.6 双重熔断（原则 7 工程化）

| 熔断类型 | 触发条件 | 行为 |
|---|---|---|
| **Token 预算熔断**（纪元代谢） | 疲劳线 80% / 凋亡线 95% | 记忆结网 → 重生 |
| **任务接力熔断** | 最大尝试次数（默认 5 次） | 任务挂起，释放资源 |
