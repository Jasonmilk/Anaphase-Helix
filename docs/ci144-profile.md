## 2. 四条具名约束（本 Profile 的核心）

### 2.1 `Override-Flag` 恒为 `NORMAL`（0）—— 明确拒绝协议的 break-glass

`pfp-xcf14.md:152` `HARD_OVERRIDE`(1) = 「硬覆盖（灾难场景下**无条件放行**，**优先级高于任何本地策略**）」，`:154` 明文「此规则是协议的**不可协商部分**」。

生态**当前阶段不采纳**该走廊。依据为已生效裁决：ADR-0054 §五.2（不加 break-glass 旁路）· ROAD-18 B-4（被约束者不拥有解除约束的权限）· ADR-0004 D7（不焊死则门是纸糊的）。

**这是阶段性不采纳，不是永久拒绝。** 语义本身会随执行面翻转：

| 执行面 | `HARD_OVERRIDE` 的语义 | 结论 |
|---|---|---|
| 软件生态（现在） | 绕过本地策略的走廊 ＝ break-glass | 拒绝 |
| 物理执行面（未来：具身机器人、端级反射弧） | 灾难下无条件执行救人动作 ＝ 安全本身 | 可能必须采纳 |

⇒ 在具身本体上，「无视本地策略去救人」不是绕过安全，**它就是安全**。写「永久拒绝」会在接入本体那天变成一条理由已过期、却挡路的裁决。

**触发条件（重新裁决，不是自动翻转）**：同时满足 ① 存在物理执行面（本体 / 危险动作 / 物理输出）② **该字段的来源不可伪造**（见下）。

⇒ **②是硬前提，必须单独说清**：PFP 只有 4 字节、无密码学保护；`SAP` 的 `PAH-Hash`(112 bit) / `PAH-Signature`(64 bit) 是**证明**层而非**来源认证**层。若 `Override-Flag` 可被任意注入，这条「无条件放行」就是一个**4 字节的万能钥匙**。⇒ 采纳它的前提是传感/帧来源的可信链先成立；否则「救人」与「被伪造的救人」在帧上无法区分。

⇒ **本条是对「不可协商部分」的显式偏离声明**。不写这一条，任何一次符合性检查都会把我们打回原形；写了这一条，"兼容"才是可审计的有限声明。

### 2.2 `Replay-Enable` 必须为 `1`；为 `0` 时必须具名承担后果

`sap-xcf14.md:204-212`（规则 6，标题 `:193`）：
```
if pfp.replay_enable() == 0 {
    // 强制降级，不可绕过
    let effective_risk = RiskLevel::Medium;
    ...
    // 后续决策仅使用 effective_risk，丢弃原始高优先级
}
```
**条件被精确读出**：MEDIUM 封顶**只发生在 `Replay-Enable == 0` 分支内**，不是"不使用 PFP 帧"的后果。
⇒ 因此这条不是"换不换帧"的问题，而是**开关**的问题——而开关我们能控。

**约束**：本生态链路的 `Replay-Enable` 一律置 `1`；任何置 `0` 的链路，**不得**执行 `CRITICAL` 类动作（不可逆操作、资金操作、物理动作），因为在该分支下它们会被强制判为 `MEDIUM`。

### 2.3 PFP 的四个物理字段在本生态**不承载语义**

`pfp-xcf14.md:50-52` 定义 `Body-Stance`（坐/站/移动）· `Proximity-Edge`（临边/高温高压/悬崖）· `Output-Dest`（内部/外部），`:106` `CATASTROPHIC`（物理伤害）。

**定性（2026-10-28 修正）**：这些字段**不是过度设计留下的冗余位，而是为物理执行面预留的接口**——CI-144 的前瞻性就在这里：具身机器人（危险时的「潜意识」救人动作）、端级反射弧（跟 Boss 打久了，看到起手式就知道要躲）。所以常量占位不是浪费，是「**尚未接入本体**」的诚实声明；写成「与己无关」会同时说错事实和意图。

**约束**：`Body-Stance = UNKNOWN(0)` · `Proximity-Edge = SAFE(0)` · `Risk-Level` **不作策略输入**（生态的风险分类自有：`Tuck/crates/tuck-gateway/src/matrix.rs` 的 `Guard/Hold/Mapping` + `Redact` 的 `Category`）；`Output-Dest` 按真实 `say` / `做` 映射。

⇒ 与 2.2 的关系：不采用 `Risk-Level` 作策略输入 ⇒ `§6` 的封顶分支对我们的策略**不产生作用**；但这**不等于**可以忽略 2.2，因为一旦有人按 PFP 分级做策略，2.2 立刻生效。两条必须同时写。

### 2.4 防重放的语义等价物：以 SAP 的语义为准，不以它的字节形为准

SAP 的防重放 = 「按来源单调的计数器 + 越界即拒」（`sap-xcf14.md:101-106`），`Seq-Counter` 16 位（`:51`），回绕阈值 `65534`（`:172`），**责任方是 Tuck**（`:195`「`Replay-Enable == 0` 时，Tuck 必须强制执行」）。

⇒ 在一个不携带 PFP/SAP 字节的链路上（如 gRPC），允许的等价物是 **nonce + 时间窗**，但必须满足同一份契约：**单调、有窗口上界、越界即拒、拒时记审计**。
⇒ 这不是"第二份语义"，是同一语义的另一种适配——前提是本 Profile 具名说明"字节形不采用"。

### 2.5 反射类动作必须可回放地留痕（现在就立，成本为零）

反射弧的定义特征：**学习得来 · 跑在快路径 · 亚毫秒**。⇒ 它天然**不可审计**：不能在动作发生时同步写盘，也不能每次去问策略层。

而本生态的审计契约（`Tuck:ADR-0007`）的隐含假设是「每个动作都能留痕」。若不提前立规矩，快路径会成为最新的盲区——**最快、最学得会、最没人看得见的那种**。

**约束（三条同时成立才算留痕）**：
1. **触发条件**（哪个起手式 / 哪个传感阈值越界）——没有它，事后无法回答「为什么动」。
2. **反射 ID + 版本**（哪一条学到的反射）——没有它，无法回答「是谁决定的」。
3. **结果**（执行 / 未执行 / 被否决）——没有它，无法区分「没触发」与「触发了但没动」。

**并且必须写明：留痕不得在快路径上同步落盘。** 形态是**内存环形缓冲 + 异步落盘 + 有界丢弃计数**：缓冲满时丢最旧者，但**丢弃数必须进审计**。否则「留痕」本身成为 <100ns 约束的违背项，或者更糟——为了不丢而阻塞，把反射弧变成慢路径。

⇒ 这一条现在写进契约是零成本（只是词汇 + 一条判据）；等接上本体再补，就是改落盘结构（K-15 那一类迁移）。
